ADK

Agent Development Kit

Framework open-source que torna dev de agentes = dev de software tradicional.

Agent
Encapsula instruções + modelo Gemini + conjunto de Tools. Unidade base.
Session / State / Memory / Event
Session = container da conversa. State = memória curta (dict mutável). Memory = recall entre sessões. Event = registro imutável.
Runner
Motor de execução. Orquestra Events, atualiza State, invoca LLM e coordena Tools.
Workflow Agents
Orquestram sub-agentes. Tipos: Sequential, Parallel, Loop.
Callbacks
Injeta lógica no ciclo de vida. Ex: after_agent_callback extrai resumo final do State.
★ Novidades ADK
Skills Registry (local + Google Cloud) para capacidades reutilizáveis. Suporte A2A 1.x nativo. to_mcp_server — um agente ADK pode ser exposto como servidor MCP.

MCP

Model Context Protocol — agente ↔ ferramenta

Padrão aberto que resolve o problema de N integrações customizadas para cada combinação de app de IA + fonte de dados. Interface universal via arquitetura cliente-servidor.

list_tools — cliente descobre ferramentas disponíveis (nome, descrição, JSON schema).
call_tool — executa ferramenta: nome + argumentos → resultado.
Evolução do transporte
stdio local (dev)HTTP + SSE remoto (prod)
SSE permite múltiplos clientes compartilharem um servidor, centraliza gestão de ferramentas e mantém API keys no servidor.

A2A

Agent-to-Agent — agente ↔ agente

Enquanto MCP resolve agente-para-ferramenta, A2A resolve agente-para-agente. Protocolo aberto anunciado em abr/2025 e transferido em jun/2025 para Linux Foundation (governança neutra).

Agent Card
JSON público em /.well-known/agent.json — nome, skills, URL. Como agentes se descobrem.
A2A Server
Envolve agente ADK, expõe Agent Card e recebe tarefas. HTTP + SSE + JSON-RPC.
a2a-python
Lib concreta que faz ADK “falar” A2A — serve Agent Card e gerencia tarefas.
A2A Inspector
Ferramenta web de debug — visualiza Card, chat direto e JSON-RPC cru.
